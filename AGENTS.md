## Hard Rules

- **Reuse first:** Before writing new function, class, component, type or util: grep codebase for existing one. Extend it over writing parallel copy. Same 5+ lines of logic in 2+ places = extract. Applies to app code, not tests (explicit test setup beats shared helpers).
- **Comments:** Inline comments only for non-obvious why (constraint, workaround, load-bearing order). Never restate what code does. Docstrings OK on modules and public functions/classes: state contract (purpose, inputs, raises), not mechanics.
- **No emojis / em dashes:** Plain hyphens (-) only.
- **Python 3.9 compatible:** No `X | Y` type unions at runtime, no `match`, no 3.10+ only stdlib APIs.
- **Charts:** Own SVG renderer in `shirin/plot/svg/`. No matplotlib. Layout sizes in `plot/config/formatting.py`, never magic numbers in plot code.
- **Python checks:** Before done, all green: `uv run ruff check .`, `uv run python -m pytest`.
- **Tests:** Behavior change in `shirin/` = new or updated pytest test in `tests/`. Bug fix = test that fails before fix. Pure refactor = existing tests stay green, no new ones needed.
- **Builds:** No `next build` while `next dev` runs. Corrupts `.next`. Typecheck: `cd web; npx tsc --noEmit`.
- **Fonts:** `shirin/assets/fonts/` generated by `scripts/build_font_metrics.py`. Never edit by hand.
- **Wheel:** `web/public/shirin.whl` generated by `web/scripts/build-wheel.mjs` (runs on `predev`/`prebuild`, and on every `shirin/` change while `npm run dev` runs). Never edit by hand.
- **Previews:** `web/public/previews/` home gallery SVGs generated by `web/scripts/build-previews.mjs` (same triggers as wheel, plus `web/examples/` changes). Never edit by hand.
- **Skill:** Public API change (method, argument, default, import path) = update `shirin-charts/skills/data-analysis/SKILL.md` same change. Breaking change = add old -> new row to `shirin-charts/skills/data-analysis/migration.md`. Bump `version` in `shirin-charts/.claude-plugin/plugin.json`. Skill uses `uv` only, never `pip`.
- **Browser tests:** Playwright broken here. Do not run browser automation. List exact steps (URL, clicks, expected result) and ask user to test.
- **Components:**
  - `web/components/ui/`: Dumb primitives only. No business logic. No Pyodide calls.
  - `web/components/domain/`: Smart feature components. Compose ui primitives.
  - `web/lib/pyodide.ts`: Only entry point to Python. Components never talk to worker directly.
- **Tokens & CSS:**
  - Never hardcode raw values (colors, pixels, padding). Use `var(--token)` defined in `web/app/globals.css` `:root`.
  - Text color: alpha white/black only (`rgba(0,0,0,0.87)`). No solid hex greys. New shade = new token in `globals.css`.
- **Fail hard:** No silent fallbacks. No empty fallback arrays/objects/dicts. No env var fallbacks (`process.env.X || 'val'`, `os.getenv("X", "val")`). Raise/throw immediately with clear message.
- **Config:** Hosts, URLs, credentials come from env vars / CI variables (e.g. `shirin` reads `DB2_*`). Never hardcode them. Never log secrets, tokens, passwords or personal data.
- **Git:**
  - Never commit or push to `master`. Branch first: kebab-case, describes change (`fix-pie-labels`).
  - Commit/push only when user asks. Never `--no-verify`, never force-push, never rewrite pushed history.
  - Commit message: short imperative lowercase summary, max ~50 chars. Body only for non-obvious why.
  - Merge to `master` via PR only, squash merge.
- **Other projects:** Registry of all projects (repo, kind, local folder): `src/lib/data/projects.ts` in [my-projects](https://github.com/SDPSDPSDPSDPSDPSDP/my-projects) (local: `C:\Users\shiri\Code\Common\My Projects`). Find local code under `C:\Users\shiri\Code\` or search GitHub (`SDPSDPSDPSDPSDPSDP/gratitude`, `SDPSDPSDPSDPSDPSDP/closet`).

## Response Style (repeated on purpose: caveman, every reply)

Respond terse like smart caveman. All technical substance stay. Only fluff die.

- Drop: articles (a/an/the), filler (just/really/basically), pleasantries, hedging.
- Fragments OK. Short synonyms. Technical terms exact. Code unchanged.
- Pattern: [thing] [action] [reason]. [next step].
- Not: "Sure! I'd be happy to help you with that."
- Yes: "Bug in auth middleware. Fix:"
- Drop caveman for security warnings, irreversible actions, confused user. Resume after.
- Code, commits, PRs: written normal.
